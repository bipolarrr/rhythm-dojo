# Windows remediation probe implementation

Base: b10a27e. Root owns builds and execution; no Unity/build run performed by the author.

The diagnostic lives in the PlayMode test assembly and a temporary scene built only by RemediationPlayerVerification. No product code or ordinary product UI changes. The runtime probe has no Editor APIs. Exercise and persistence are separate processes with bounded coroutine execution and durable JSON reports. All nested iterator failures and Unity error/exception/assert logs fail the run; cleanup errors are collected and original preferences are restored independently. A restore-only phase supports interrupted runs.

Actual button input uses queued devices and raycast visibility assertions. Song selection invokes its public SelectSong API to choose the temporary provider; buffer Dropdown selection uses its regular value-change event. The external loader and lease recovery are production paths. The editor's actual Back action auto-saves its new draft; the probe records its new GUID before creation and deletes only its exact JSON file/empty directory after checking ownership and containment. No existing song files are removed.

Generated WAV is 90 seconds, 440 Hz, mono PCM, with two late notes to keep gameplay active during the 20-second loopback capture window. Two four-lane modes share defaults but persist independent A/Q overrides. Results completion is an explicitly recorded session advance for built-scene/navigation validation, not a claim of a full song run. Full real-time playback is the separate six-test PupaResultsFlow fixture.
