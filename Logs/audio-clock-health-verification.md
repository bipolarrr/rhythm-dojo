# 오디오 오류 수정 및 검증 — 2026-10-31

기존 로그에서 발견된 타이틀 음악의 설정 참조 누락과 작은 DSP 버퍼에서의 재생 속도 저하를 대상으로 수정했다. 기존 이름과 인터페이스는 유지했다.

## 수정

- 타이틀 음악이 활성화될 때 설정이 없으면 다시 로드한다.
- 오디오 재설정 이벤트 뒤 다음 프레임에 타이틀 음악을 재개한다. 실제 임포트 음원으로 출력 샘플까지 검사했다.
- 버퍼 적용 후 준비 시간 0.3초와 측정 시간 1초 동안 원본 DSP 시간/실제 시간 비율을 검사한다. 0.85~1.15 범위 밖이면 더 큰 버퍼로 재설정하고 다시 검사한다. 정상 동작하는 작은 버퍼는 유지한다.
- 검사 도중 설정창 닫기와 중복 적용을 막고, 강제 화면 전환 시 이전 설정을 복원한다. 실제 적용된 버퍼와 복구 결과를 설정창에 표시한다.
- 설정창 씬과 팝업 프리팹만 다시 생성했다.

## 실측

| 요청 samples | 수정 전 DSP/실제 시간 | 수정 후 실제 samples | 수정 후 DSP/실제 시간 |
| --- | --- | --- | --- |
| 32 | 0.199 | 256 | 1.003 |
| 64 | 0.201 | 256 | 1.003 |
| 128 | 0.200 | 256 | 1.002 |
| 256 | 0.992 | 256 | 0.997 |
| 512 | 0.998 | 512 | 0.997 |
| 1024 | 0.986 | 1024 | 1.007 |
| 2048 | 0.980 | 2048 | 1.049 |

엔진/장치의 32~128 버퍼 자체를 정상화한 것은 아니다. 이 환경에서는 비정상 속도를 감지해 검증된 256 버퍼로 복구한다. 표시용 곡 시계를 배율 보정하는 방식은 사용하지 않았다. 실제 AudioSource 재생 위치의 시간 진행과 재시작도 통과했다. 청감상 잡음과 지연 시간은 측정하지 않았다.

원본 측정: `audio-buffers-before-clock-validation.txt`. 수정 후 측정: `audio-buffers.txt`.

## 검증 결과

- 컴파일 오류 0.
- EditMode: AudioSettingsServiceTests 9개 통과. 느린 버퍼 자동 복구, 정상 저버퍼 유지, 복구 실패 종료, 적용 거절, 취소, 일시 중단, 드라이버 강제 보정 포함.
- PlayMode: 서로 다른 테스트 20개 최종 통과. AudioFlowTests 5개, SettingsFlowTests 9개, GameplayPauseFlowTests 2개, 기본 화면 전환 Smoke 4개.
- 일시정지 중 실제 버퍼 적용·복구 후 3-2-1 카운트다운을 거쳐 같은 곡으로 복귀하는 경로 포함.
- 초기 실패: 타이틀 재설정 테스트 1개와 검사 완료 전 닫기를 시도하던 기존 설정 테스트 2개. 수정 후 해당 테스트와 영향을 받는 경로를 재검증했다.
- CLI 실행기가 테스트를 시작하지 못해 프로젝트 검증 실행기로 전환했다. 이미 통과한 테스트는 관련 변경이 없는 한 반복하지 않았다.
- 전체 프로젝트 재검증 대신 변경에 관련된 범위를 실행했다. 초기/재검증 결과 XML의 테스트 이름을 합쳐 PlayMode 20개가 모두 Passed인 것을 확인했다.

근거: `audio-health-playmode-initial.xml`, `audio-health-regression-initial.xml`, `verification-audiohealthfinal.xml`.
