# 테스트 실행 비용 및 검증 지침 개편

2026-11-09 · Unity 6000.3.23f1 · 기준 HEAD `664c127716b99581fc81146ac3b44c135b86dd5c` 및 작업 시작 시점의 미커밋 변경

일상 기능 검사는 해당 기능의 Fast·SceneIntegration만 선택하도록 변경하였다. 실제 장치와 전체 곡 재생 검사는 Hardware·Endurance로 보존하였다. 공통 정리 비용, 씬 생성 검사, 구형 규칙 검증과 에이전트 실행 지침을 함께 개편하였다.

## 구현 범위

- 메뉴와 CLI는 같은 프로필 선택기를 사용한다. 기능·비용 교집합, 비용 분류 누락·중복, 전체 범위 누락을 검사하며 0개·skip·inconclusive를 성공으로 처리하지 않는다. 요약은 프로필·고유 사례 수·결과·시간·실패 상세로 제한하고 개별 결과는 XML에 보관한다.
- 오디오 설정값과 변경 이벤트를 추적하여 변경이 없으면 teardown의 Reset을 생략한다. 장치 재설정 이벤트가 있으면 동일 설정값도 복구한다. 입력·설정·구독 복원은 유지하며 Workspace는 빈 정리 씬으로 전환하고 소유 객체만 정리한다.
- 초기화에 제한시간과 실패 원인을 추가하였다. 체력 규칙은 짧은 전용 채보로 검증하고 대표 실제 DSP·입력·결과 연결은 유지하였다.
- 전체 씬 생성은 한 시나리오에서 두 번만 수행한다. 7개 씬·프리팹·이미지·필수 참조·Build Settings·콘텐츠·GUID를 확인한다. 파일과 Editor 상태는 성공·예외 후 복원한다. 설정 마이그레이션 분기는 에디터 내부 메모리 객체로 분리하였다.
- 감사 대상 43개는 현행 PlayRules로 이관하고 26개는 Compatibility로 보존하였다. 중복 후보 6개의 고유 조건은 유지 검사로 통합하였다. UI 참조·자원 소유권·클릭 영역·겹침·넘침과 잘못된 BPM 힌트를 검증하도록 기존 사례를 보완하였다. 대응 내역은 [감사 대응표](../Docs/test-verification-migration.csv)에 기록하였다.
- [AGENTS.md](../AGENTS.md)에는 의무 규칙을, [검증 안내](../Docs/verification.md)에는 프로필·명령·선택 기준을 정리하였다.

## 검증 결과

빌드 없는 전체 범위를 한 차례 실행하고 실패 범위만 재검증하였다. 최초 EditMode는 470개 중 466개 통과, 4개 실패였다. 재입력 공백별 Miss 기대값과 HUD 검사의 카메라 의존을 수정하여 해당 범위가 통과하였다. 이어서 아직 실행하지 않았던 전체 PlayMode를 수행하였다. 후속 메뉴 검사는 명시된 현판 크기 계약 보존을 확인하였다.

최신 결과를 사례 이름으로 합산한 고유 700개는 모두 통과하였으며 skip·inconclusive는 없다. 단일 전체 실행의 무실패 결과가 아니다. 개별 실행 원본은 [최초 EditMode](verification-rework/all-first-editmode.xml), [전체 PlayMode](verification-rework/all-playmode.xml), [후속 결과를 합산한 XML](verification-rework/consolidated.xml)에 보관하였다. 합산 XML의 각 사례에는 원본 결과 파일이 명시되어 있다. Smoke와 프로필 분류·선택 검증도 통과하였다. Windows 플레이어 빌드는 실행하지 않았다.

최초 실패의 원인과 조치:

| 범위 | 원인 | 조치 |
| --- | --- | --- |
| RegrabPreservesEndpointsAndMatchesFrameSweeps(Automatic) | 1.6초 재입력에서는 유지 판정 공백에 Miss가 없는데 통합 과정에서 양수로 기대 | 재입력 시각별 기대값 분리, Automatic·Release 재검증 |
| HudLayoutSupportsLaneCountsWithoutController(4/5/6) | 이전 검사가 남긴 카메라에 의존 | 테스트 소유 카메라 생성, 기존 카메라 상태 복원, 생성 객체 정리 후 세 사례 재검증 |

## 시간 측정

이전 저장된 실행 기록을 기준선으로 사용하였다. 기준선 확보를 위한 전체 재실행은 하지 않았다. 아래 값은 개별 사례 duration의 합이며 프로필 실행의 Editor 진입·종료 비용을 포함한 wall time이 아니다.

### 동일 검사 범위

Workspace의 동일한 58개 사례는 이전 124.48초에서 이번 96.16초로 측정되었다(22.8% 감소). 기존 실행과 이번 실행의 환경·순서 차이가 있으므로 전체 감소분을 특정 정리 변경의 효과로 단정하지 않는다.

씬 생성은 이전 두 검사 합계 24.09초, 이번 통합 검사 24.25초였다. 생성 횟수를 두 번으로 통합하면서 전체 7개 씬과 생성 에셋의 검증을 확장하였으며, 이 구간의 실행 시간 감소는 확인되지 않았다.

### 비용 분리에 따른 기본 프로필 범위

아래 제외 시간은 해당 기능 태그 중 AssetGeneration·Hardware·Endurance 사례의 이번 측정 합이다. 같은 검사를 더 빨리 실행한 효과와 구분한다.

| 기능 | 기본 사례 수 | 기본 사례 시간 | 별도 비용 사례 수 | 별도 비용 사례 시간 |
| --- | ---: | ---: | ---: | ---: |
| UI | 120 | 181.51초 | 8 | 42.68초 |
| Gameplay | 370 | 133.15초 | 33 | 401.03초 |
| Authoring | 155 | 127.17초 | 0 | 0.00초 |

기능 태그는 서로 겹칠 수 있으므로 행을 합산하지 않는다. [전체 수치와 사례 증감](verification-rework/summary.json)에 비용별 분류·시간과 원본 범위의 대응을 보관하였다.

## 보존 및 확인

작업 시작 시 존재하던 런타임 코드·씬·프리팹·이미지의 미커밋 변경을 보존하였다. 이번 소스 변경은 테스트와 에디터 도구로 한정하며 게임 동작·저장 형식·런타임 호환 API는 제거하지 않았다. 기존 703개에서 통합으로 7개 사례를 제거하고 프로필·복원 경계 4개 사례를 추가하여 700개가 되었다. 제거 항목과 보존 대상은 대응표 및 합산 결과의 원본 이름으로 추적할 수 있다.

Unity 검증은 Windows 데스크톱 Editor에서 수행하였다. SSH 배치 PlayMode는 그래픽 창 초기화 단계에서 종료되어 유효한 테스트 결과로 집계하지 않았다. 해당 시도의 임시 씬은 외부에 백업 후 정리하였다. 검증 완료 후 Editor 정리 종료와 ready 상태, 소스·에셋·meta 해시 일치를 확인하였다. 소스 diff 공백 검사와 문서 문체·구조 검사도 수행하였다.
