# 마우스 호버 피드백 검증

2026-11-17 · `emergency` · Unity 6000.3.23f1

현재 노출되는 버튼, 메뉴, 선택 항목과 설정 컨트롤에 미세 확대와 주홍색 붓 원을 적용했다. 기존 `DojoButtonFocus`가 포인터와 키보드 입력을 함께 관리하고, 씬 빌더가 시각 효과의 참조를 준비한다. 기존 작업 폴더의 수련·대화 관련 변경은 유지했다.

## 크기와 방향 후속 조정

최신 확대 조정: 사용자 요청에 따라 호버 배율을 1.14로 높였다. 기존 선택 강조가 있는 캡션은 `1.14 / 1.025`를 추가 배율로 사용해 합산 크기를 맞춘다. 0.14초 Ease-Out, 붓 원의 크기와 굵기, 클릭 영역은 유지했다. [14% 확대 검증](hover-scale-14-tests.json) 3개 통과: 렌더링된 글자·먹 배경 배율, 이탈 원복, 클릭 경계, 키보드 선택, 비활성 상태, 빠른 이동 및 화면 전환을 확인했다. 컴파일 오류 없음. 설정·곡 목록 화면을 갱신했다.

확대 가시성 조정: 일반 버튼의 호버 배율을 1.04에서 1.07로 높였다. 기존 `DojoControlFocus`가 2.5% 확대하는 캡션에만 4% 추가 배율을 유지해 합성 배율은 약 1.066이 된다. 먹 배경과 일반 캡션은 모두 7% 확대하고 클릭 영역은 유지한다. 기존 회귀에 실제 ModeSelection의 설정·다음 모드 버튼을 추가해 글자와 먹 배경의 렌더링된 메시가 1.07배로 커지고 이탈 시 원복되는지 확인했다. [호버 확대 검증](hover-scale-tests.json) 3개 통과, 컴파일 오류 없음. 클릭·키보드 선택·비활성 상태·빠른 이동·화면 전환도 같은 실행에서 통과했다.

Editor 재실행 후 ModeSelection 설정 버튼의 메시 폭도 39에서 41.73으로 증가함을 확인했다([측정](hover-scale-probe.json), [진입 전](../Docs/verification-images/hover-scale-before.png), [진입 후](../Docs/verification-images/hover-scale-during.png)). 임시 입력 장치와 입력 설정은 측정 후 복원했다.

최신 굵기 조정: 이전 40% 확대 상태를 재실행 화면에서 확인한 뒤, 굵기 기준을 그 상태의 두 배인 2.8배로 올렸다. 시작부터 붓을 굵게 누르고 진행할수록 필압을 줄이며 마지막 14% 구간에서 가는 끝으로 빠지도록 했다. 굵은 부분은 바깥으로 퍼지게 해 캡션을 가리지 않는다. 원의 기준 크기·방향·0.22초 그리기 시간은 유지했다. [최종 호버 회귀](hover-weight-final-tests.json) 3개 통과, 컴파일 오류 없음. 첨부 화면도 이 굵기로 갱신했다.

사용자 요청에 따라 붓 원의 진행 경로를 상하 반전했다. 기존 오른쪽 위 시작점이 오른쪽 아래로 바뀌며, 필압과 마른 붓 질감도 같은 경로를 따른다. 글자가 있는 버튼은 배경 판넬 대신 글자 범위로 원을 맞춘다. 원의 가로·세로 배수는 1.30/1.60에서 1.14/1.24로, 추가 여백은 10에서 6픽셀로 줄였다.

작은 버튼 캡션과 문자 기호의 기본 글자 크기를 약 10% 키웠다. 큰 방 제목은 유지하며, 자동 맞춤을 사용하는 버튼은 최대 크기만 함께 늘려 긴 문구가 잘리지 않게 했다. 공통 빌더에서 새 시각 컴포넌트를 준비할 때 한 번 적용하므로 씬 저장이나 준비를 반복해도 크기가 누적되지 않는다. 직렬화 변경을 비교해 버튼 글자 크기 224곳과 관련 최대 크기 24곳 외에 위치·클릭 영역·계층 변경이 없음을 확인했다.

최종 확인: [호버 회귀](hover-refinement-tests.json) 3개, [글꼴·저장 화면](hover-refinement-typography-tests.json) 11개, [Smoke](hover-refinement-smoke-summary.txt) 5개 모두 통과했다. [붓 경로 검사](hover-refinement-direction.json)와 실제 설정·곡 목록 화면도 확인했다. 전체 테스트와 빌드는 실행하지 않았다. 아래 기록은 최초 구현 때의 검증이며, 첨부 화면은 후속 조정을 반영한다.

## 동작과 적용

- 0.14초 cubic ease-out으로 일반 그래픽을 1.14배 확대한다. 기존 선택 강조가 있는 글자도 두 효과를 합쳐 1.14배가 된다. `RectTransform`, 레이아웃, 클릭 영역은 바꾸지 않는다.
- 기존 `DojoScreenStyle.Vermilion`과 `DojoInkGraphic`의 마른 붓 표현 방식을 사용한다. 굵기·곡률·불투명도가 일정하지 않은 붓 원을 0.22초 동안 그리며, 포인터가 머무르면 유지하고 이탈하면 사라진다. 클릭은 재연출 조건이 아니다.
- 실제 렌더링된 글자·이미지의 크기로 타원을 배치한다. 스크롤 영역의 클리핑을 따른다. 장식 그래픽에는 Raycast가 없다.
- 최상위 Raycast 대상과 활성·상호작용 상태를 검사한다. 부모 CanvasGroup 비활성화, 숨긴 컨트롤, 모달 배경, 드롭다운 목록의 빈 배경은 강조하지 않는다. 기존 키보드 선택과 포인터 선택 콜백은 유지한다.
- 커서의 기존 캔버스 안에 미리 만든 원 두 개를 재사용한다. 빠른 이동, 포커스 상실, 컨트롤 비활성화, 씬 전환 시 정리한다. 컨트롤마다 독립 애니메이터나 런타임 생성 코드를 붙이지 않는다.
- Title, ModeSelection, SongSelection, Gameplay, Tutorial, Results, Settings, ChartEditor 및 SettingsPopup에 적용했다. 데이터에 따라 생성되는 곡·프로젝트 행과 드롭다운 항목은 기존 템플릿에서 효과를 상속한다. 폐기된 화면이나 숨긴 버튼을 활성화하지 않았다. 채보 편집용 캔버스와 결과 그래프의 좌표 입력은 변경하지 않았다.

## 검증

| 범위 | 결과와 근거 |
| --- | --- |
| 기존 커서 동작 | 기존 5개 사례 통과. [결과](hover-cursor-tests.json)의 기존 커서 사례 참조. 같은 실행에서 발견한 신규 호버 테스트 문제는 아래 최종 실행으로 재검증했다. |
| 신규 호버 회귀 | 3개 통과, 실패·건너뜀 없음. 확대 중 경계 안팎 Raycast, 반복 클릭의 실제 즐겨찾기 변경과 원 유지, 이탈 원복, 키보드 전환, 비활성 컨트롤/부모, 모달 배경, 앱 포커스 상실, 빠른 이동, 씬 전환 후 동일한 원 재사용. [최종 결과](hover-regressions-tests.json) |
| 설정 입력 | 슬라이더 클릭·키보드 값 조정·드롭다운·중첩 팝업·포커스 복구 통과. [결과](hover-settings-tests.json) |
| 편집기 메뉴 | 클릭 열기, 호버로 메뉴 전환, 메뉴 고정, 취소 관련 2개 사례 통과. [결과](hover-editor-tests.json) |
| 모드 재진입 | 마우스·키보드·게임패드 조작과 반복 이동, 구형 UI 비활성 유지 통과. [결과](hover-mode-tests.json) |
| 설정 재열기 | 모달의 중복 열기·닫기, 인스턴스 재사용, 입력 차단과 포커스 복구 통과. [결과](hover-reopen-tests.json) |
| Smoke | 5개 통과, 실패·건너뜀 없음. 실행 37.15초, 전체 정리 포함 49.84초. [요약](hover-smoke-summary.txt), [XML](hover-smoke-playmode.xml) |

설정 재열기 테스트의 구형 기대값도 현재 프리팹과 빌더에 맞춰 수정했다. 도장 배경을 숨겨야 한다는 기존 검사가 현재 표시 방식과 달랐으며, 배경의 런타임 동작은 변경하지 않았다.

컴파일 오류 없음. 변경 전 깨끗했던 씬·설정 프리팹은 추가한 호버 컴포넌트를 제외하면 기존 직렬화 내용이 같음을 확인했다. 에디터 저장 시 자동 보정된 폰트 제한값과 캔버스 배율은 원래 값으로 복원했다. 전체 테스트와 플레이어 빌드는 실행하지 않았다.
