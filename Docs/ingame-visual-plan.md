# Gameplay의 횡스크롤 수련 무대

곡의 재생 구간을 네 등분한다. 오른쪽 수련 공간에서 수련자의 발과 타격 지점이 보이고, 중앙에는 기존 레인과 판정선이 들어온다. 장면 경계에서는 배경 카메라가 옆 무대로 이동한다. 이동하는 동안 양쪽 무대의 동작이 이어진다.

| 곡 구간 | 무대와 움직임 | Gameplay 캡처 |
| --- | --- | --- |
| 0–25% | 도장 마당에서 두 수련자가 거리를 좁혀 주먹과 발차기를 주고받는다. 상대가 반격하거나 충격에 물러나는 동안 깃발과 단풍잎도 움직인다. | [도장 마당](verification-images/action-courtyard.jpg) |
| 25–50% | 바위 위에 앉은 수련자가 숨을 들이쉬고 양손으로 물을 가른다. 폭포 본류, 전후의 물줄기, 어깨와 바위에서 튀는 물방울, 수면 파동이 서로 다른 주기로 움직인다. | [폭포 수련](verification-images/action-waterfall.jpg) |
| 50–75% | 산길에서 발을 교차하며 달리고 통나무를 뛰어넘거나 낮은 가지 아래로 숙인다. 먼 봉우리, 삼림, 달리는 지면, 가까운 나무와 바위 순으로 스크롤 속도가 빨라진다. | [산길 질주](verification-images/action-race.jpg) |
| 75–100% | 수련자가 목인 앞에서 잽·반대손 주먹·높은 발차기를 엮는다. 접촉 포즈를 잠깐 유지하고 목인 윗부분이 돌아갔다 복귀한다. 연타 사이의 휴식에는 두 발을 짚고 포권한다. | [목인 수련](verification-images/action-timber.jpg) |

Windows용 Unity 6000.3.23f1의 1920×1080 Game View에서 연속 384프레임을 캡처했다. 영상은 16초 검증 채보의 시계를 24fps로 진행시키고 입력을 판정기에 전달한 결과다. 배경 카메라, 레인과 HUD가 함께 보인다. 영상 출력은 1280×720이며 소리 트랙은 생략했다. [16초 재생 영상](verification-images/action-stages.mp4)

## 시계와 판정

`GameplayBackgroundDirector`는 플레이 세션의 곡 시각, `TempoMap`, 판정 결과를 읽는다. 수련 루틴과 환경은 입력이 없어도 진행한다. 노트 머리의 Good·Perfect는 순간 타격, 달리기 가속 포즈 또는 물 가르기를 강조한다. Miss와 헛입력에는 짧은 회복 동작을 쓴다. 동시 입력은 하나의 동작으로 묶고, 롱노트 중간·끝 판정은 성과 집계에 반영한다. 일시정지와 예약 재개 중에는 화면을 고정하고 재시작 때는 동작과 판정 이력을 초기화한다.

자유 연습에서 전곡의 판정 조건을 충족하면 마지막 목인이 쓰러진다. 강습과 편집기 테스트 플레이도 동일한 네 무대를 사용하며 각 모드의 기존 종료·복귀 절차를 따른다.

## 씬과 아트

`Game Tools > Scenes > Build Gameplay`와 `Build All Scenes`가 같은 `GameplayBackgroundBuilder`를 호출한다. 빌더가 전용 표시 카메라, 네 무대, 캐릭터·그림자·소품·효과를 씬에 배치하고 참조를 직렬화한다. 레인 카메라는 기존 `GameplayViewport`에 계속 그린다. 무대 셰이더는 패널의 폭을 계산할 때 URP 직교 카메라 반폭의 두 배를 사용한다.

전용 원화와 스프라이트 시트는 `Assets/Game/Art/ActionStages/`에 있다. `ActionStageArtwork`가 Point 필터 원본을 고정 셀로 잘라 Sprite 하위 에셋으로 보관한다. 전신 동작에는 수련자 24포즈와 대련 상대 색상이 따로 있다. [내장 ImageGen 제작 프롬프트](training-journey-art-prompts.json)

`DojoBackgroundFlowTests`는 실제 씬에서 무대별 포즈 변화, 일시정지·재시작, 롱노트, 전곡 성과에 따른 마무리를 검증한다. 무대 카메라로 수련자를 표시한 프레임과 숨긴 프레임을 읽어 실제로 픽셀이 그려지는지도 비교한다. `RHYTHM_DOJO_CAPTURE=1`로 Editor를 시작하고 이 fixture를 실행하면 `Logs/action-stages/frames`에 합성된 Game View 프레임이 저장된다.

## 확인 결과

Unity 6000.3.23f1에서 관련 Domain/EditMode·PlayMode 검사 33건이 통과했다. 검증 범위에는 곡 선택부터 실제 곡 재생·결과·재시도까지의 흐름, 강습과 편집기 복귀, 판정선 투영, 일시정지·재개·재시작이 포함된다. Gameplay를 다시 생성하고 저장본을 열어 무대 아트 의존성 27개가 일치하는 것을 확인했다. 16:9 Game View 캡처에 더해 4:3과 21:9에서도 네 무대의 양쪽 화면 끝과 수련자가 그려지는지 카메라 출력으로 검사했다. Windows 플레이어 빌드는 이번 검증 범위에서 제외했다.
